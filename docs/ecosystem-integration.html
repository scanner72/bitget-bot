Карта

Два мира экосистемы

1. Agent Hub — для разработчиков

Открытый toolkit: подключаешь AI-агента (Cursor, Claude, Codex, свой бот) к бирже Bitget через официальные API-обёртки.

SDK · CLI (bgc) · MCP · Skills · Signal

2. Playbook / GetAgent — для трейдера

Продукт внутри Bitget AI: готовые сценарии стратегий, суб-аккаунт, UI «выбрал и запустил». Не то же самое, что Hub CLI.

Для хакатона — бонус/нарратив, не обязательный код

Слой 0

Что общее у всех путей Hub

  • Снизу одна биржа: UTA v3 (Unified Trading Account) — spot, futures, account…
  • ~89 операций, сверху — 14 intent-глаголов (order, position, market…)
  • Ключи: live API Key или отдельный Demo API Key
  • Безопасный режим: флаг --paper-trading → Bitget Demo (не «блокчейн-тестнет»)
  • Дополнительно: --read-only, --dry-run, подтверждение на опасные write

Demo ≠ наш локальный paper в C:\bitget-bot. Demo — официальная песочница биржи.

Путь A

SDK — библиотека в коде

Пакет · bitget-agent-sdk (TypeScript)

Что это

Типизированный клиент: каталог операций, REST, rate-limit, mock. Твой Python/TS-сервис импортирует SDK и сам вызывает place/cancel/positions.

Когда брать

Основной путь для встройки в Divergent Agent Desk: слой exec вместо локального paper → Demo/live через официальный клиент.

# идея интеграции
signal → decide(LLM/rules) → risk → exec_sdk.place(order)
                              ↑
                     BITGET_* + paperTrading: true
Путь B

CLI — bgc из терминала

Пакет · bitget-agent-cli

Что это

Командная строка поверх SDK. Агент или скрипт говорит: «открой лонг» → bgc --paper-trading order --action place …

Когда брать

Быстрые смоуки, shell-агенты (Claude Code / Codex), демо «человек в терминале». Не идеально как ядро долгого desk-loop.

bgc --paper-trading account get_account_assets
bgc --paper-trading order --action place …
Путь C

MCP — инструменты в Cursor / Claude

Пакет · bitget-agent-mcp

Что это

Локальный MCP-сервер: у ИИ в IDE появляются «кнопки» Bitget (intent + discover + raw). Ордера — через те же Demo/live ключи.

Когда брать

Демо судьям «агент в Cursor торгует на Demo». Для нашего Docker-desk — опционально рядом, не вместо SDK в пайплайне.

args: ["-y", "@bitget-ai/bitget-agent-mcp", "--paper-trading"]
env:  BITGET_API_KEY / SECRET / PASSPHRASE  ← Demo keys
Путь D

Skills — «как правильно звать биржу»

Пакет · bitget-agent-skill

Что это

Markdown-инструкции для терминального AI: когда demo, когда confirm, как не смешать live/demo, recovery по ошибкам.

Когда брать

Если демо идёт через Cursor/Claude + bgc/MCP. Для нашего Python-desk skills не обязательны — важны для «vibe»-агента рядом.

Skill сам по себе ордера не шлёт — учит модель не ломать API.

Путь E

Signal — рынок без ключа

Пакет · bitget-signal (отдельно от UTA trade)

Что это

Рыночная аналитика / сигналы Bitget без торгового API-ключа. Не исполнение ордеров.

Когда брать

Доп. фича: обогатить decide() внешним signal feed. Наш RSI-divergence остаётся ядром; Signal — опциональный вход.

Путь F

Playbook (GetAgent) — продукт, не SDK

  • Готовые workflow: условия → сигнал → риск → exec на изолированном суб-аккаунте
  • Пользователь выбирает/настраивает в UI GetAgent (Plus/Pro)
  • Под капотом Agent Harness (координация моделей + риск + аудит)

Как «интегрировать» для хакатона

Не обязательно публиковать в библиотеку Playbook. Достаточно: архитектура 1:1 (signal→risk→exec→audit) + текст «совместимо с идеей Playbook / Agent-Native Exchange». Полный publish — если Bitget откроет third-party.

План работ

Практическая интеграция (по шагам)

  1. Создать Demo API Key на bitget.com (API Management / Demo).
  2. Добавить в desk адаптер exec/bitget_hub.py (или TS sidecar) с режимом EXEC_MODE=hub_demo|paper|live.
  3. Маппинг наших ордеров → UTA place/cancel/positions; SL/TP оставить своим менеджером или биржевым — выбрать одно и задокументировать.
  4. Опционально: MCP с --paper-trading для видео «агент в Cursor».
  5. В README / SUBMISSION: «исполнение через Agent Hub Demo; сигнал — свой Divergent».
  6. Playbook: один слайд + формулировка compatibility, без ожидания publish API.
